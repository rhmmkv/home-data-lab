# Проверки данных Olist

Проверки определяют, какие расчёты допустимы на выбранных данных. Они охватывают импорт девяти CSV и свойства заказов и отзывов, необходимые для анализа доставки. Полная проверка всех таблиц, ключей и связей набора не выполнена.

## Импорт и идентификаторы заказов

Количество строк всех девяти таблиц совпало с соответствующими CSV. Ожидаемые количества — в [описании источника](../../data/README.md); запрос сверки — [SQL 02](../../sql/olist/02_verify_counts.sql).

[SQL 04](../../sql/olist/04_orders_initial_checks.sql):

| Проверка `orders` | Результат |
|---|---:|
| Строк | 99 441 |
| Уникальных `order_id` | 99 441 |
| Пропусков `order_id` | 0 |
| Пропусков `order_purchase_timestamp` | 0 |

Заказ можно использовать как единицу анализа. Совпадение количества строк с CSV подтверждает полноту импорта этих файлов; оно не доказывает полноту покрытия бизнеса исходной выгрузкой.

## Временное покрытие

[SQL 05–07](../../sql/olist/README.md) показывают даты оформления с 4 сентября 2016 года по 17 октября 2018 года. Сумма месячных количеств равна 99 441.

В результате группировки представлены 25 месяцев; за ноябрь 2016 года заказов нет. В сентябре 2018 года — 16 заказов, в октябре — 4, среди них нет `delivered`. Состав статусов в конце ряда отличается от основной части данных. Причины этих особенностей не установлены.

Поэтому уменьшение месячных количеств описывает выгрузку и не трактуется как доказанное падение заказов всего бизнеса. Расчёты доставки используют все заказы, отвечающие правилам выборки, без дополнительного фильтра по времени.

## Статусы и дата доставки

[SQL 08](../../sql/olist/08_delivery_dates_by_status.sql):

| Статус | Заказов | С фактической датой | Без фактической даты |
|---|---:|---:|---:|
| `delivered` | 96 478 | 96 470 | 8 |
| `canceled` | 625 | 6 | 619 |
| `shipped` | 1 107 | 0 | 1 107 |
| `unavailable` | 609 | 0 | 609 |
| `invoiced` | 314 | 0 | 314 |
| `processing` | 301 | 0 | 301 |
| `created` | 5 | 0 | 5 |
| `approved` | 2 | 0 | 2 |
| **Всего** | **99 441** | **96 476** | **2 965** |

Последний столбец — разность числа заказов и числа заполненных дат. Статус `delivered` и наличие даты доставки не являются совпадающими признаками. Для анализа отбираются только `delivered` с обеими датами: 96 470 заказов. Причины необычных сочетаний статусов и дат не установлены.

Предполагаемая дата в исходных заказах записана с временем `00:00`. Это условие важно для эквивалентности календарного определения опоздания и границы следующего дня в SQL 09, 12, 13 и 15.

## Несколько отзывов на заказ

Исходная таблица отзывов содержит 99 224 строки и 98 673 уникальных заказа. Прямое соединение с ней может размножить заказы.

[SQL 11](../../sql/olist/11_latest_order_reviews.sql) выбирает записи с максимальным `review_answer_timestamp` внутри заказа. После отбора:

| Проверка | Результат |
|---|---:|
| Строк | 98 673 |
| Уникальных заказов | 98 673 |

Таким образом, на исходном наборе выбран ровно один последний ответ на каждый заказ с отзывом. При равенстве максимальных времён запрос может вернуть несколько строк, поэтому при обновлении данных проверку нужно повторить. Правило не объясняет происхождение нескольких отзывов и не означает исправление предыдущей оценки.

## Соединение и покрытие оценками

[SQL 12](../../sql/olist/12_delivery_reviews_join_checks.sql) использует `LEFT JOIN`, чтобы сохранить выбранные доставки независимо от наличия оценки:

| Проверка после соединения | Результат |
|---|---:|
| Строк | 96 470 |
| Уникальных заказов | 96 470 |
| Заказов с оценкой | 95 824 |
| Заказов без присоединённой оценки | 646 |

Соединение не размножило и не потеряло заказы. Для средней оценки и доли оценок 1–2 используются только заказы с известной оценкой внутри каждой группы доставки. Поэтому знаменатель этих показателей отличается от знаменателя доли опозданий.
